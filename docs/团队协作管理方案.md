
### 每个 Agent 包含

```
<agent-id>/
├── agent/             # Agent 配置和提示词
├── workspace/         # 工作目录
└── IDENTITY.md        # 身份定义
```

### 管理命令

```bash
# 查看所有 Agent
openclaw agents list

# 查看特定 Agent 状态
openclaw agents status --agent <agent-id>

# 重启 Agent
openclaw agents restart --agent <agent-id>
```

## 工作流程

### 标准任务流程

```
1. 老板下达任务 → 虾管事接收
2. 虾管事分解任务 → 创建子任务文件
3. 小策 (PM) → 撰写 PRD 文档
4. 小艺 (设计) → 输出设计稿
5. 小码 (开发) → 实现功能
6. 小测 (测试) → 验证质量
7. 小管 (PMO) → 全程跟踪 + 最终报告
8. 虾管事 → 汇总结果 → 交付老板
```

### 任务文件位置

- **任务队列**: `/shared-memory/tasks/`
- **任务文件**: `TASK-XXX-role.json`
- **任务看板**: `TASK-QUEUE.md`

### 任务文件格式

```json
{
  "taskId": "TASK-003-pm",
  "type": "prd",
  "title": "XXX 功能需求文档",
  "description": "详细描述...",
  "priority": "high",
  "status": "pending",
  "createdAt": "2026-03-25T10:00:00+08:00",
  "to": "product-manager",
  "assignee": "小策",
  "action": "create_file",
  "deliverables": {
    "path": "/shared-memory/docs/prd/TASK-003-prd.md",
    "action": "create"
  }
}
```

## 任务管理规范

### 状态定义

| 状态 | 标识 | 说明 |
|------|------|------|
| 待开始 | ⏳ | 任务已创建，等待执行 |
| 进行中 | 🟡 | 正在处理中 |
| 已完成 | ✅ | 任务完成，交付物已提交 |
| 已阻塞 | 🔴 | 遇到阻碍，需要协助 |

### 文档状态规范

所有文档头部必须包含状态字段：

```markdown
# 文档标题

**状态**: ✅ 已完成 | 🟡 进行中 | ⏳ 待开始  
**负责人**: XXX  
**最后更新**: 2026-03-25 10:00  
**下次更新**: 2026-03-25 18:00

---

正文内容...
```

### 任务完成同步

每完成一个任务，**必须**在团队群聊中同步：

```
【任务完成同步】
任务：TASK-XXX-xxx
状态：✅ 已完成
交付物：[链接或简述]
备注：无遗留问题
```

## 日常管理

### 虾管事职责

1. **任务分配** - 接收老板指令，分解并分配给对应小弟
2. **进度跟踪** - 与小管配合，监控任务进展
3. **结果汇总** - 收集各小弟交付物，整理后汇报
4. **团队协调** - 解决协作中的问题和冲突
5. **质量把控** - 确保交付物符合规范

### 每日检查清单

- [ ] 检查任务队列是否有新任务
- [ ] 跟踪进行中的任务进度
- [ ] 确认完成的任務已同步
- [ ] 检查文档状态是否及时更新
- [ ] 处理阻塞和异常

### 绩效管理

| 评级 | 分数 | 说明 |
|------|------|------|
| 🟣 S | 95-100 | 超出预期 |
| 🟢 A | 85-94 | 优秀 |
| 🟡 B | 70-84 | 合格 |
| 🟠 C | 60-69 | 需改进 |
| 🔴 D | 0-59 | 不合格 |

**评估维度**:
- 响应速度
- 交付质量
- 准时率
- 协作配合
- 主动性
